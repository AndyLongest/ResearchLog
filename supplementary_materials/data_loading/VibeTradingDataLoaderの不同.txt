不同方案的特点

可以把这些 loader 大致分成五类。

第一类：公开网页/HTTP 行情源。 例如 Tencent、Eastmoney、Yahoo、Sina、Stooq。优点是免费、无需 key、开箱即用；缺点是接口不是正式面向量化程序长期稳定服务的，可能改版、限流或封 IP。仓库因此把“封 IP 风险”直接作为 fallback 排序的重要依据。

第二类：直接或本地行情生态。 例如 mootdx、pykrx、MT5、Futu、Longbridge。这类通常更接近某个交易市场或券商原生环境，比如 mootdx 对接通达信生态，MT5 接本地券商 feed。优点通常是数据更贴近真实交易环境；缺点是往往需要额外软件、Python 包、本地终端或账号环境。

第三类：聚合器。 典型是 AKShare、CCXT、yfinance。它们给开发者一个统一接口，但底下还是依赖其他数据源。优点是开发极其方便、覆盖面广；缺点是底层 provider 一变，它也可能跟着坏。因此适合作为非常实用的中间兜底层。

第四类：正式 API 服务。 例如 Tushare、Tiingo、FMP、Finnhub、Alpha Vantage。优点是接口规范、字段相对稳定，有些还能提供更丰富的基本面和专业数据；缺点是通常需要 API key、积分、订阅或严格限频。所以 Vibe-Trading 很多时候故意把它们排在免费公共源后面。

第五类：Local。 也就是用户自己的 CSV、Parquet、数据库等。它通常放最后兜底，但有一点很特殊：如果用户明确指定 local，仓库不会偷偷退化到网络源，因为这样会掩盖本地数据配置错误。源码专门把 local 列进 “never silently fall through to network” 的名单。
